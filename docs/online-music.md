# 在线音乐：网站要满足的格式

设备上的「点歌」功能不依赖哪个固定的音乐网站：网站地址在网页设置页的「在线音乐」卡片里填，存在设备上。固件只认**一种页面格式**，写的时候参照的是某个“热门歌曲在线试听与 MP3 下载”类的站点。这类站常换域名、也常整站消失：失效了就照下面的格式找一个同款的，把地址填进去，不用改固件。

## 怎么用

1. 打开网页设置页（设置 → 网络里有地址和二维码），在「在线音乐」卡片的「音乐网站」里填首页地址，比如 `http://example.com`（只填域名也行，会自动补 `http://`），点保存。
2. 在下面的「试一下」里搜一首歌、点「播放」。能放就说明这个网站可以用。
3. 之后跟它说「放一首晴天」「来首周杰伦的歌」「换一首」就行。收听页最左边的「音乐」标签显示专辑封面、进度和滚动歌词。快进快退、停止和播客共用（「快进一分钟」「别放了」）。

网站支持的话，地址尽量写 `http://`：设备的内部内存同时只够一条加密连接（HTTPS），对话本身就要占一条。音频和封面不管你填的是哪种，设备都会先试 http。

## 页面格式

设备只按固定的文字标记去页面里取数据，不运行网页里的脚本。下面的 `{网站}` 是你填的地址，末尾不带 `/`。

### 1. 搜索页：`{网站}/so/{关键词}/`

关键词按 URL 编码（中文是 `%E6%99%B4...`，空格是 `%20`），用 GET 请求，返回 HTML。设备会：

- 找每个 `data-rid="歌曲编号"`，从这里到下一个 `data-rid=` 之间算一条结果；
- 在这一段里取 `result-title">歌名<` 和 `result-artist">歌手<`；
- 最多取前 10 条。

一条结果的样子：

```html
<div class="result-item" data-rid="228908">
  <div class="result-info">
    <div class="result-title">晴天</div>
    <div class="result-artist">周杰伦</div>
```

一条结果都没有时，页面里如果有 `search-results` 这个词（这类站搜索结果区的 id），就当成“真的没搜到”；没有就当成网站不能用（换了格式、或者跳到了别的页面）。

### 2. 歌曲页：`{网站}/song/{歌曲编号}/`

取三样东西：

| 内容 | 页面里的样子 | 必须有吗 |
|---|---|---|
| 音频地址 | 脚本里一行 `let code = "aHR0cDovL..."`，引号里是音频直链的 base64 | 必须 |
| 专辑封面 | `<img id="album-cover" ... src="封面地址">` | 可以没有 |
| 歌词 | `lyrics-container` 后面一串 `<div class="lyric-line" data-time="12">歌词</div>`，`data-time` 是第几秒开始唱 | 可以没有 |

### 3. 音频

- 格式：MP3、AAC（ADTS）或 m4a。设备看文件开头几个字节认格式，不信扩展名和 Content-Type，因为这类站常把 m4a 写成 `.aac`。m4a 的目录（moov）在文件开头最好，在末尾也能放，只是开始得慢一点。
- 要支持 Range 请求（按字节范围下载），否则快进快退会从头下载。
- 音频地址里带签名和过期时间也没关系：每次点歌都会重新取歌曲页。
- MP3 的总时长按 128kbps 估算（这类站给的 MP3 基本都是 128k），m4a 的时长从目录里算，是准的。

## 怎么判断一个新网站能不能用

先看几个特征：

- 网页标题像「歌手《歌名》MP3下载-歌曲在线试听」，搜索结果页标题像「XX歌曲大全-MP3下载与在线试听」；
- 搜索后的网址是 `/so/关键词/`，点进一首歌是 `/song/一串数字/`；
- 在歌曲页按 Ctrl+U 看源代码，能搜到 `let code = "`。

然后在电脑上用三条命令验证（把 `example.com` 换成要试的网站）：

```bash
# 1. 搜索页里有没有 data-rid 和歌名
curl -s "http://example.com/so/%E6%99%B4%E5%A4%A9/" | grep -o 'data-rid="[0-9]*"' | head -3

# 2. 歌曲页里有没有音频地址（把 228908 换成上一步搜到的编号），解出来应该是 http(s) 开头的地址
curl -s "http://example.com/song/228908/" | grep -o 'let code = "[^"]*"' | cut -d'"' -f2 | base64 -d; echo

# 3. 音频能不能下：看到 200 和 audio/... 就行（把下面的地址换成上一步解出来的）
curl -sI "上一步解出来的地址" | grep -iE "^HTTP|content-type"
```

三步都过，填进设置页、在「试一下」里搜一首放出来就行。

## 出错时它会说什么

| 提示 | 意思 |
|---|---|
| 还没设置音乐网站 | 设置页里没填 |
| 音乐网站连不上，或者页面格式变了 | 搜索页打不开，或者打开了但不是上面那种格式。多半是网站失效了，换一个 |
| 歌曲页里没找到音频地址 | 歌曲页格式变了（没有 `let code = "`） |
| 这首的音频打不开 | 音频地址下载不了、或者下下来不是音频（常见于下架的歌）。设备会自动试搜索结果里的下一首，最多试 3 首 |
| 没搜到 | 网站正常，就是没有这首歌，换个说法试试 |

## 已知的限制

- 只认上面这一种页面格式。别的音乐网站（接口不同、要登录、要签名）需要另写适配。
- 歌放完就停，不会自动放下一首；说「换一首」放的是上次搜索结果里的下一首。
- 歌词跟着播放进度按秒切换。进度按“送进播放队列的声音”计算，比实际听到的稍微超前一点。
- 这类网站的歌曲版权情况不明，请自行判断用不用。
